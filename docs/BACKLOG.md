## 6. 打断当前任务（仅主人）

当前状态（2026-10-29）：命令入口已实现，接收层处理 `/stop` 与 `/tasks`，绕过聊天队列和会话锁。`/stop` 停前台，`/stop 编号` 停指定后台，`/stop all` 停本会话全部后台；区分请求、确认、失败和未开始任务的取消。不能据此保证任意外部子操作都即时退出或自动回滚。实现见 `task_commands.py`、`tasks.py`，已有停止、恢复与会话隔离测试。以下保留原始目标。

原始问题：长任务占用 worker 时，后续消息会排队，主人无法及时叫停。
目标：主人能在当前聊天中打断正在执行的任务，及时收到停止状态。

验收标准：

- 提供明确的打断命令（现为 `/stop`），处理不等待当前任务执行完毕
- 仅主人可用，且只能打断当前会话的任务；不能通过群聊停止私聊任务或其他会话任务
- 向执行端发出取消请求，并区分“已请求停止”“已确认停止”和“停止失败”；不能只停止发送回复却声称任务已停
- 说明已完成的操作及仍在运行、无法立即取消的操作；打断不自动回滚已发生的文件修改或外部动作
- 无运行中任务、重复打断及取消失败时，都给出明确反馈；停止后仍可继续聊天或发起新任务
- 补测试，覆盖权限、会话隔离、长任务期间及时响应、取消成功与失败、重复打断和后续任务恢复；同一提交更新 FEATURES、ARCHITECTURE、CHANGELOG

剩余／限制：自然语言“停一下”尚无桥接级确定触发；后台停止与排队取消已实现。`send_to_task` 仅向同任务下一轮追加要求，不是打断正在执行的轮次；重启后无法确认结束的任务仍需人工核实，不能自动放锁。

## 10. 细碎文本以文件交付，避免聊天刷屏

验收标准：

- 对多段短文本、逐条修改稿等容易产生大量消息的交付内容，优先生成文件发送，不再在聊天中重复贴出全文
- 普通纯文本使用 `.txt`，需要结构或 Markdown 格式时使用 `.md`；保留原本应交付的完整内容与换行
- 文件只发送到当前会话，成功后简短说明文件名；发送失败时明确告知，不自动改成大量文字消息刷屏
- 主人明确要求在聊天里直接展示时，遵从当次要求

依赖：文件发送能力，关联第 3 项。当前仅记录需求，暂不修改消息切分和发送逻辑。
