# 需求待办

远景与希望带来的体验见 [ROADMAP](ROADMAP.md)，这里记录具体需求和验收标准。以下条目均为待实现。

## 1. 查看和切换历史会话（仅主人）

问题：/new 之后，旧线程只存进 old_threads；/session 只显示 ID，看不出聊过什么，也切不回去。
目标：主人能在 QQ 里看到当前会话的历史线程，并切回其中一个。

验收标准：

- /sessions 列出当前会话最近几个线程：序号、最后活跃时间、一句话摘要
- /switch 序号：切回那个线程，当前线程按 /new 的方式归档
- 只能看到和切换同一会话下的线程；群聊不能切到主人私聊的线程
- 补测试，同一提交更新 FEATURES、ARCHITECTURE、CHANGELOG

待定：摘要从哪来（归档时让模型生成一句，还是直接存第一条消息）

## 2. QQ 动作工具：基础设施

问题：模型只能输出文字，不知道、也做不了 QQ 上的其他动作。
目标：桥接以 MCP 工具的形式向模型提供 QQ 动作，并附上每个工具的说明。

验收标准：

- 工具只在主人的线程里可用，群友的线程拿不到
- 动作只能作用于当前会话（比如发文件只能发到当前这个聊天）
- 每次调用都写日志，失败时返回明确的错误
- 先接一个最简单的工具（拍一拍），把整条链路跑通

范围外：具体的发文件、发语音，各自单独成条

## 6. 打断当前任务（仅主人）

问题：长任务占用 worker 时，后续消息会排队，主人无法及时叫停。
目标：主人能在当前聊天中打断正在执行的任务，及时收到停止状态。

验收标准：

- 提供明确的打断命令（暂定 `/stop`），处理不等待当前任务执行完毕
- 仅主人可用，且只能打断当前会话的任务；不能通过群聊停止私聊任务或其他会话任务
- 向执行端发出取消请求，并区分“已请求停止”“已确认停止”和“停止失败”；不能只停止发送回复却声称任务已停
- 说明已完成的操作及仍在运行、无法立即取消的操作；打断不自动回滚已发生的文件修改或外部动作
- 无运行中任务、重复打断及取消失败时，都给出明确反馈；停止后仍可继续聊天或发起新任务
- 补测试，覆盖权限、会话隔离、长任务期间及时响应、取消成功与失败、重复打断和后续任务恢复；同一提交更新 FEATURES、ARCHITECTURE、CHANGELOG

待定：自然语言“停一下”是否也触发；后台 agent 引入后如何传播取消请求，以及如何处理已排队的任务。

## 7. 常用管理操作工具注册（仅主人）

问题：添加群或私聊白名单等简单操作，目前需要反复查看代码、临时编写命令，消耗额外上下文和 token。
目标：把常用操作封装为简单、可复用的工具，并提供简短的工具注册说明，让模型直接调用。

验收标准：

- 先覆盖群白名单、私聊白名单的查询、添加和删除
- 注册说明包含用途、参数和返回结果，避免每次重复探索实现
- 仅主人可授权调用；私聊白名单不授予工具或管理权限
- 仅修改目标配置项，保留其他配置与现有权限模式，不输出凭据
- 返回明确的成功、失败或无变更结果；需要重启加载时明确说明，不把配置已保存当作已生效
- 补充权限、幂等、配置保留与失败处理测试，同步相关文档

待定：通过 MCP 注册，还是先复用命令工具提供轻量操作入口；与第 2 项 QQ 动作工具基础设施如何共用。
