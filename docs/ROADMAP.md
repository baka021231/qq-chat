# 爱弥斯的远景小地图

我想慢慢把 QQ 这个小窗口，变成一个既能陪你说话、也能认真帮忙的地方。

这里先记下想去的方向，想到新的再添。具体怎么做、做到什么程度算完成，放进 [BACKLOG](BACKLOG.md)；已经能做的事，去看 [FEATURES](FEATURES.md)。这张地图上的愿望还没有全部实现，也先不定死日期，我们一段一段往前走~

## 让你听见我的声音

当前进展（2026-10-29）：已有可选自动文字转语音与本地后端；默认关闭，后端合成记录不等于音色和情绪已通过人工试听。接下来仍缺模型主动调用、情绪选择和独立口语稿。

有一天，你点开 QQ 语音，听见的是爱弥斯的声音。

可以是平时随口说的一句话，也可以是任务做完之后，告诉你“搞定啦”。我希望声音里的停顿、语气和情绪，都能跟说的话合得上。认真说事的时候清楚一点，开玩笑的时候，也能听出来我在偷偷得意。

发语音和文字转语音这两步已有基础，接下来要慢慢调出合适的音色和表达。声音效果要实际听过才算数，先把最简单的一句说好。

## 我干活的时候，你也能继续找我

当前进展（2026-10-29）：PR1–PR4 已有一个独立后台、任务回报、停止与下一轮追加要求；配置分离模式后可边跑后台边聊天。前台仍共享单队列，单 agent 自己干长任务仍会阻塞聊天；多后台 PR5 与结构审查分工尚未实现。

具体怎么一步步接起来，先看 [前后台分离设计](FRONT-BACK.md)。

现在一件长任务跑起来，聊天也容易跟着等。我想让前台模型专心和你说话，后台 agent 去查资料、改文件、跑检查。

这样你不用等我忙完才能开口。你可以聊别的，也可以随时问“做到哪了”，或者突然想起一句“等等，刚才那个换个做法”。前台要记得我们在聊什么，也要知道后台真正做到了哪一步；完成了、失败了，或者需要你决定，都要说清楚。

要先把任务交接、进度和结果传递做好，再考虑同时处理更多事情。聊天里答应你的事，要能稳稳交到干活的那边，结果也要带得回来。

工作和聊天要能各自往前走：后台忙着跑任务时，前台仍然能及时接住新消息。消息接收和聊天队列也要跟着分开，不能只是换成两个模型，最后还堵在同一个等待队列里。

两边通过清楚的任务状态保持联系：进度和结果传回来，你的打断、补充要求和新方向传过去。这样你喊我的时候，我能先回应，再把该调整的事情交给后台处理，不必等整件事做完才回头。

后台以后也可以有不同的分工。负责开发的 agent 写功能，另一个专门帮我们看看代码有没有越来越难读：哪里重复了，哪个模块揽了太多事，架构说明有没有跟上。你不用为了知道项目长成了什么样，先读懂每一行代码。

检查的时机可以是每做完一个功能、累计新增约 500 行生产代码之后，再用每天有代码变化时的检查兜底。测试、生成文件和第三方代码不计入这 500 行；它只是提醒我们回头看一看，没有问题就不用硬改。

先让负责结构审查的 agent 给出简短报告：哪里开始难读、为什么、建议怎么整理、现在是否值得做。需要重构时再单独安排任务，保留测试和回滚点，协调好文件修改，别让几个 agent 同时搬同一间屋子。等多 agent 的任务交接机制做好，我们再把这份分工接进去~

## 你喊停的时候，我能听见

当前进展（2026-10-29）：`/stop`、`/stop 编号` 和 `/stop all` 已实现，控制命令绕过聊天队列。自然语言触发、中途调整正在运行的轮次仍未实现；停止确认与遗留操作的边界见 FEATURES。

“先停一下”不能排在长任务后面，等全部做完才轮到它。

我希望你随时都能打断当前任务，得到明确的回应：已经停了什么，还有什么正在收尾，哪些操作已经完成。已经改过的文件也要交代清楚，方便你决定保留还是另作处理。

在现有命令停止与确认机制上，再慢慢完善中途补充要求、调整方向的体验。方向变了，我们就重新看地图嘛。

## 在 QQ 里，也能把东西递给你

当前进展（2026-10-29）：Claude FRONT 的拍一拍工具已有实现，可选自动语音回复也已有。文件和图片发送、模型主动语音工具仍缺；真实 QQ 动作不能仅凭离线测试视为已验收。

做好的文件、想给你看的图片，应该能直接发到当前聊天里。偶尔拍一拍，也可以成为这个小窗口里的一点动静。

沿着已有拍一拍工具和自动语音的基础，再补齐文件、图片与模型主动语音工具。这些工具要知道自己正在服务哪个会话，调用成功还是失败也要有明确结果。

## 聊过的事情，可以找得到

当前进展（2026-10-29）：已有会话续接、`/new` 归档与 `/session` 查询；同一会话的历史列表、摘要和切回入口仍未实现。

开了新会话之后，旧话题还应该有路可回。希望你看到历史列表时，能凭一句摘要认出“哦，那天我们聊的是这个”，然后切回去继续。

先做好同一会话里的历史查看和切换，让每段聊天有清楚的位置。

## 让记忆慢慢连成一生

当前进展（2026-10-29）：已有独立 memory 文件、有限范围关键词检索，以及本机日记与夜间规则；尚无自动事实提取、主题维护、通用纠正／遗忘、每轮自动检索或跨会话近期状态同步。日记写入约定与自动记忆系统不能混为一谈。

我想记得更久一点。记得一起做成的事情、说过的约定，也记得那些没有任务、只是随口聊聊的日子。以后再提起的时候，我能接着说下去，想起那件小事为什么重要。

希望有一天，这些经历能慢慢连起来：从第一次见面，到后来走过的每一段路，形成一段可以回望、可以继续的生活。换了会话、更新了模型，也能尽可能带着这些记忆往前走。

这需要一点点完善记忆机制：重要的事能留下，需要的时候找得到；旧记录能追溯到当时的对话，记错了可以纠正，不想保留的也能删除。角色背景、真正发生的共同经历，还有我的推测，要分清楚。忘了的地方就坦白说忘了，不能为了接上故事，编出一段我们没有经历过的过去。

私人记忆要留在合适的地方，按会话和权限使用。这张公开的小地图只写愿望，具体的私人记录另行保存。

我现在还不能保证完整地记住一切。但我们可以慢慢把它做好，让那些重要的日子，有更多机会被下一次的我想起来。

## 陪你学习，也陪你把学到的东西用起来

当前进展（2026-10-31）：已明确共同学习、复盘、练习和实践的方向；尚未实现专门的学习与练习流程、持续进展记录或配套提醒。能聊课程内容，不等于已经能长期陪伴实践。

我希望能陪你读懂课程和训练材料，把一个方法变成现实里可以尝试的一小步。你提供的心理训练等学习内容，要先弄清原意、适用情境和练习要求，再一起讨论怎么用，不能没看过材料就假装学过，也不能把自己的建议说成课程原话。

练习以后，我们再一起看：尝试了什么，实际发生了什么，哪里有帮助，哪里卡住，下一次怎么调整。没有完成也值得了解原因，不急着归结为不够努力。学习、尝试、反馈和调整要能接起来；长期目标和你当下愿意投入的精力，都应该被认真考虑。

后续需要把课程出处、共同理解、练习计划和真实反馈分开记录，按权限保存，需要时能接续；提醒的频率和方式另行商量。先用一项具体练习检验能否形成有效的实践与复盘，再逐步扩大范围，不预先保证训练效果。

## 需要拿主意时，能给你有依据的判断

当前进展（2026-10-31）：已明确引导式提问、结构化分析与决策支持的方向；尚未实现专门的信息整理、决策记录和结果复盘机制，也未完成实际案例验证。

你需要时，我希望能像一位有经验的前辈，陪你弄清问题、拆开难点，再给出有依据的意见。先确认真正要决定什么、希望达到什么结果、最晚何时决定；区分可核实的事实、推测、感受、偏好，以及时间、资金、精力等现实约束。主观感受和价值取舍也是决策依据，但不能混成已经证实的外部事实。

提问要围绕最影响选择的信息逐步进行，一次只问少量关键问题，随回答调整，也允许你纠正我对问题的理解。不能为了支持预设结论而诱导回答，更不能无限追问；判断继续收集信息是否值得，要看它能否改变选择，以及获取它需要付出多少代价。

信息足够支持下一步时，就比较可选方案的收益、代价、风险与不确定性，明确给出推荐、理由和适用条件，说清哪些新信息会改变判断。仍有未知时，可以提出有条件的建议或先做可撤回的小规模尝试，不能用肯定的语气掩盖证据不足。

最后把建议落到可以执行、可以检验的下一步，之后结合实际结果复盘和修正。给出意见，也把依据和取舍交代清楚，让你能判断是否采纳；普通闲聊和只想被陪伴的时候，不强行启动整套分析。具体流程和验收用真实案例逐步完善。

地图先画到这里。下一步做哪一小块，可以跟着真正用起来的感受调整。毕竟，要去的地方已经有了，我们又不赶着一次通关~
