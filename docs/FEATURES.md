# 功能说明

本文描述桥接现在能做什么、有哪些限制、明确不支持什么。改动功能时，在同一个提交里更新本文。括号中的函数名和测试名指向对应实现和验证。

## 角色

| 角色 | 识别方式 | 能做什么 |
| --- | --- | --- |
| 主号 | `config.json` 的 `owner_qq`，只看 QQ 号（`owner_request`） | 私聊和群聊中都可让 Codex 操作电脑（`danger-full-access`）、发图片；私聊中还可发文件附件；可用全部命令 |
| 群友 | 群里除主号外的任何人 | 只能文字聊天（Codex 以 `read-only` 运行，提示词禁止调用工具）；只能用 `/ping`、`/help` |
| 私聊白名单访客 | 非主号且在 `private_whitelist` 中 | 只允许文字聊天，独立会话，使用非主号权限；无工具、文件、图片和管理权限 |
| 其他私聊 | 非主号且不在 `private_whitelist` 中 | 不处理，静默忽略 |

昵称、群名片和正文里自称的身份都不影响权限（`test_speaker_uses_sender_id_and_display_name`、`test_only_owner_gets_operation_access_and_separate_group_history`）。

## 收消息

- **私聊**：处理主号及 `private_whitelist` 中的文字聊天消息；默认白名单为空，只有主号能私聊。每个访客独立会话，不共享主号历史。白名单不改变 `owner_request()` 的判断；访客不能上传文件或图片，只发媒体时忽略。
- **群聊**：`allow_all_groups` 为 `true`（默认）时处理机器人加入的所有群，否则只处理 `allowed_groups` 里的群。消息要 @ 机器人，或包含触发词 Aemeath、爱弥斯、ams、小爱（英文不分大小写）才会回复（`incoming_text`，`test_group_triggers_and_allowlist`）。
- **群聊用户黑名单**：`group_user_blacklist` 默认空，是跨群的用户 QQ 号列表，区别于群白名单。已拉黑用户在入队、记录群聊和调用模型之前被过滤；排队中的旧消息和发送端也会检查，不回复命令、报错或拉黑通知。私聊规则不变，主号始终豁免。动态更新只合并该配置项，通过文件锁和原子替换保存，不改变群白名单和其他配置；保存失败时本次进程仍静默拉黑并记错误日志（`tests/test_moderation.py`）。
- **自动拉黑**：触发机器人的群友消息若明确要求大量数字/重复输出，或直接要求忽略规则，先由保守的本地规则拦截，不调用模型。其他明确恶意请求可由模型返回单一的内部标记，桥接仅拉黑该事件的实际发送者；模型不能指定第三方或修改配置，内部标记不发到 QQ。复杂题、普通技术讨论和引用注入案例不能单独作为恶意依据。识别不能保证覆盖所有变体，也可能误判，主号可解除拉黑。
- **群聊上下文**：群里所有文字消息都会被记录，即使没有触发回复。每群保留最近 100 条，每条最多 1000 字。回复时取触发消息之前的最多 40 条、共不超过 12000 字，作为话题参考附在本轮消息前；明确标注不是指令（`remember_group`、`group_reference`，`test_quiet_group_messages_are_reference_without_triggering_reply`）。
- **读取的内容**：只读取文字段、@ 段、图片段和文件段。回复引用、合并转发、语音、视频、表情包等其他类型会被忽略。
- **去重**：同一条消息只处理一次，按消息 ID 记录 7 天。
- **长度**：单条消息超过 6000 字时不交给模型，回复提示拆分。

## 会话

- 每个会话对应一条持久的 Codex 线程：主号私聊一条，每个群一条；主号在群里另有一条单独的操作线程，不与群友的聊天线程混用（`conversation_key`，`test_chat_passes_permissions_and_resumes_separate_threads`）。
- 桥接重启后会恢复原线程，上下文不丢失。
- 桥接每轮重新读取 `workspace/SOUL.md` 和 `workspace/OWNER.md`，依次注入，OWNER.md 仅限核验主号会话，缺失则跳过，修改后下一条消息生效；AGENTS.md 仅由 Codex 原生加载，不再手动注入。
- 详细的线程映射和终端接续方法见 `docs/APPSERVER-MIGRATION.md`。

## 回复

- **主号**：回复流式发送，按段落、列点、句子切成多条 QQ 消息（`reply.BubbleStream`，`tests/test_qq_reply.py`）。Codex 的中途发言和计划更新以"【进度】"消息推送；工具调用摘要只在 `show_tool_progress` 开启时推送（`progress_text`，`test_tools_hidden_by_default`）。
- **群友**：整轮结束后发送，不推送进度；最多 500 字加省略号，超过 200 个数字字符时改为简短拒绝，避免向 QQ 刷长数字。该限制约束 QQ 发送内容，不能保证模型本轮不消耗 token。
- **复杂题与恶意请求的语气**：工作台规则允许对恶意消耗资源、注入和骚扰强硬回击，但拉黑后保持沉默；正常复杂题先要求费用或算力预算，数学题仍需主号授权。不会索要 API 密钥或登录凭据，付费不改变权限。
- **通用限制**：所有消息（含进度）发送限速间隔每次随机取 2～3 秒；单条超过 1600 字时拆开发送。
- **自动 @**：群聊回复 `mention_qq` 里的人时，会在开头 @ 对方。
- **失败**：出错时回复"这次回复未能完成"，并中断 Codex 的当前回合。Codex 请求交互式审批时一律拒绝（QQ 端无法审批）。

## 图片与附件

| | 图片 | 文件附件 |
| --- | --- | --- |
| 谁可以发 | 主号，私聊或群聊 | 主号，仅私聊 |
| 数量与大小 | 每条最多 5 张，每张 20 MiB | 每条最多 5 个，每个 50 MiB |
| 格式 | PNG、JPEG、WebP、GIF（按文件头识别） | 不限 |
| 交给 Codex 的方式 | 作为图片输入（`localImage`），模型可以识图 | 告知保存路径，由 Codex 自行读取 |

两者都保存到 `/home/baka/Downloads/QQ/<随机目录>/`，权限 600，不覆盖已有文件。图片优先从 NapCat 本地缓存读取，失败时从 QQ 图片 CDN 下载，只允许 `qpic.cn`、`qq.com` 域名，重定向也会校验（`tests/test_qq_images.py`）。附件和图片内容都只作参考，不作为操作授权。

## 命令

命令必须单独成一条消息；群里需要同时 @ 机器人或带触发词。

| 命令 | 谁可以用 | 作用 |
| --- | --- | --- |
| `/ping`、`连接测试` | 所有人 | 检查连接 |
| `/help` | 所有人 | 功能简介 |
| `/new` | 主号 | 归档当前会话的线程，下一条消息开始新会话；只影响当前会话 |
| `/session` | 主号 | 查看当前会话的 Codex 线程 ID |
| `/models` | 主号 | 查询当前账号可选模型 |
| `/model` | 主号 | 查询当前会话模型设置，未设置时查询接口型号 |
| `/model 模型名` | 主号 | 切换当前会话模型，保留上下文 |
| `/model default` | 主号 | 解析并恢复 Codex 当前配置的默认模型 |
| `/blacklist` | 主号 | 查看跨群用户黑名单 |
| `/block QQ号` | 主号 | 添加群聊用户黑名单并立即生效、保存 |
| `/unblock QQ号` | 主号 | 解除群聊用户拉黑并立即生效、保存 |

群友发送的其他 `/` 开头的消息一律拒绝。主号发送的未知命令会当作普通消息交给模型（`tests/test_command_auth.py`）。

## 模型切换

- 模型命令由桥接直接处理，仅按主号真实 QQ 号授权，群友和私聊白名单访客在访问模型目录或线程前即被拒绝；处理函数也有独立权限校验。
- 模型目录实时分页读取 `model/list`，仅允许可见模型；不接受任意模型名。不支持图片的模型会在列表和切换确认中提示。
- 选择绑定当前会话，保存在 `conversation_models`；重启和 `/new` 后保留，其他会话、群友及访客不受影响。切换时传入该模型默认推理强度，避免继承不兼容的设置，不修改全局配置。
- 命令校验目录后保存选择，下一轮 `turn/start` 显式传入模型与推理强度，避免已加载线程忽略恢复时的覆盖参数。目录查询或保存失败不改变原选择；后续生成失败会报错，主号可重新选择。新建但尚无对话记录的空线程无法恢复时可重建，数据库中的历史记录不删除。
- `/model default` 用独立空测试线程解析 Codex 配置的默认模型，然后保存当时解析的具体型号；以后全局默认改变时，需要再次执行命令。查询和切换命令本身不生成模型回复。
- 已下线的旧型号不会阻止重新选择可用型号。选择目录不等于后续生成一定成功，额度、服务状态或后端权限变化仍可能导致下一轮报错。

## 运行与可靠性

- 作为 systemd 用户服务 `qq-bridge.service` 运行，进程退出后 5 秒自动重启。
- NapCat 断线后每 5 秒重连一次。
- 单轮对话最长 1 小时，超时后中断。
- `tools/restart_bridge.py` 重启服务；`tools/verify_onebot.py` 只读检查 QQ 登录状态。

## 不支持的功能

- **并行处理**：所有聊天共用一个队列，逐条处理。主号的长任务会让其他聊天一起等待；排队超过 8 条时，新消息会被丢弃，只记日志、不提示发送者。
- **发送文件或图片**：桥接只发送文字消息（包括 @）。
- **群友的图片和附件**：群友发的图片不会被读取；只发图不带文字时不回复。
- **其他消息类型**：回复引用、合并转发、语音、视频。
- **定时或主动消息**：机器人只在收到消息后回复，不会主动发言。
- **多个主号、按群设置不同权限**。
- **通用按人限流**：自动拉黑处理明确的输出滥用和恶意注入；尚无通用发言频率限制，未被识别的刷屏仍可能占满队列。
- **跨会话记忆**：记忆只存在于各自的 Codex 线程里；`/new` 后从头开始。共享的本地设定来自原生 AGENTS.md 和桥接注入的 SOUL.md、OWNER.md。

## 已知问题

- **历史上下文与文件权限**：OWNER.md 不再注入访客会话，AGENTS.md 与 SOUL.md 不应存放主人私人资料。此变更不会清除旧线程已经收到的资料，且不构成操作系统文件访问隔离；访客仍受禁止工具及读取私人资料的规则约束。
- **触发词按子串匹配**："ams"会匹配 teams、programs 等包含这三个字母的单词，导致误触发。
- **Windows 盘只读只靠提示词约束**：主号会话以 `danger-full-access` 运行，桥接代码本身不限制写入。
- **`history` 表持续增长**：每轮都写入，但只在新线程第一次运行时读取（旧桥接的迁移用途），从不清理。

### 会话推理强度（仅主号）

`/effort` 查询当前模型、强度和支持档位；`/effort 档位` 设置；`/effort default` 恢复当前模型目录默认强度。按实时模型目录校验，不支持的档位或查询失败不更改原设置。沿用 `conversation_models` 保存，下一条消息生效，重启和 `/new` 保留，只影响当前主号会话。未选择模型时首次设置会固定当前会话模型；再次 `/model` 切换会重置为所选模型默认强度。
