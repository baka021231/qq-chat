# 功能说明

本文描述桥接现在能做什么、有哪些限制、明确不支持什么。改动功能时，在同一个提交里更新本文。括号中的函数名和测试名指向对应实现和验证。

尚未实现的需求、验收标准和待定事项统一记录在 `docs/BACKLOG.md`。

## Agent 与前后台模式

PR1/PR2 已提供 Codex 和 Claude Code 适配器；没有 `agents` 配置仍使用原单 Codex。配置 `agents.front` 和 `agents.guest` 可分别选择主人和访客的 profile；`back: []` 为原单 agent 模式；配置一个后台 profile 后，主人前台用 NONE 聊天，操作由 `/task` 手动交给后台。本阶段不提供 MCP 自动派发或多个后台 profile。

Claude 访客使用 NONE：safe-mode、两个禁用 CLAUDE.md/自动记忆的环境变量及空工具列表校验；主人单 agent 使用 FULL，权限模式必须显式配置，正常加载项目规则。Claude 的回复先完整缓冲，校验工具与调用标记后再分气泡发送，因此不即时发送首字；拒绝的回复不进入历史或语音。Codex 原流式发送保留。

模型及强度按会话和 profile 分开保存，旧 Codex 设置和线程保持可用。新会话首次导入历史对所有 profile 统一采用最近 20 条、序列化后最多 8000 字、每条最多 1000 字的预算；不删除原历史。Claude 会话可续接和归档，已明确缺失的会话只重建一次并重新导入受限历史。适配器返回值仍最多 12000 字；Claude 历史保留校验过的完整顶层回复，不仅保存最后一句。

Claude `/models` 读取 profile 的配置目录，`/model default` 恢复其配置默认模型。可选推理档位仅认模型配置中的 `supportedReasoningEfforts`，未声明时不开放 `/effort` 切换。首次运行前的 Claude 模型状态来自配置别名；收到 init 后显示实际返回的型号。

## 后台任务与停止（PR3）

- 主人可用 `/task 完整目标` 创建任务，后台不读取聊天记录；桥接直接给出任务编号回执。后台运行时前台仍可聊天，前台 worker 本身仍只有一个。
- `/tasks` 列出当前会话最近十个任务；`/stop` 停当前前台轮次，`/stop 编号` 停某个后台任务，`/stop all` 停本会话后台任务并取消未开始的任务。任务只能在发起会话查看/操作，非主人使用任务命令静默。
- `/stop`、`/tasks` 不排队，不等会话锁。中断请求送达不等于停止成功；最终以执行端的 interrupted/completed/failed 结果区分停止、完成和失败，30 秒未确认继续保留 stopping 与执行锁。
- 写任务全局串行，orphaned 的旧写任务仍占锁；只读后台不受写锁影响。本阶段最多一个后台 profile、并发 1，多后台并发留待 PR5。
- 重启时 queued → interrupted，running/stopping → orphaned，通知主人；不自动查进程、不发信号、不确认旧任务结束。主人自己确认结束后，用 `/task release 编号` 人工释放。
- 任务结果保存在 `workspace/tasks/编号.md`，回报进入发起会话的历史和原语音流程。QQ 断线不取消后台，发送失败保留回报，重连补发；可能重复部分气泡，不重复生成已有回报。
- `/new` 不取消后台，结果回到该会话的新一代线程。没有配置后台时 `/task` 明确提示未配置，不改变原单 agent 行为。

## 角色

| 角色 | 识别方式 | 能做什么 |
| --- | --- | --- |
| 主人 | `config.json` 的 `owner_qq`，只看 QQ 号（`owner_request`） | 私聊和群聊中都可让 Codex 操作电脑（`danger-full-access`）、发图片；私聊中还可发文件附件；可用全部命令 |
| 群友 | 群里除主人外的任何人 | 只能文字聊天（Codex 为 `read-only` 且提示词禁止工具；Claude 为 NONE 无工具）；只能用 `/ping`、`/help` |
| 私聊白名单访客 | 非主人且在 `private_whitelist` 中 | 只允许文字聊天，独立会话，使用非主人权限；无工具、文件、图片和管理权限 |
| 其他私聊 | 非主人且不在 `private_whitelist` 中 | 不处理，静默忽略 |

昵称、群名片和正文里自称的身份都不影响权限（`test_speaker_uses_sender_id_and_display_name`、`test_only_owner_gets_operation_access_and_separate_group_history`）。

## 收消息

- **私聊**：处理主人及 `private_whitelist` 中的文字聊天消息；默认白名单为空，只有主人能私聊。每个访客独立会话，不共享主人历史。白名单不改变 `owner_request()` 的判断；访客不能上传文件或图片，只发媒体时忽略。
- **群聊**：`allow_all_groups` 为 `true`（默认）时处理机器人加入的所有群，否则只处理 `allowed_groups` 里的群。消息要 @ 机器人，或包含触发词 Aemeath、爱弥斯、ams、小爱（英文不分大小写）才会回复（`incoming_text`，`test_group_triggers_and_allowlist`）。
- **群聊用户黑名单**：`group_user_blacklist` 默认空，是跨群的用户 QQ 号列表，区别于群白名单。已拉黑用户在入队、记录群聊和调用模型之前被过滤；排队中的旧消息和发送端也会检查，不回复命令、报错或拉黑通知。私聊规则不变，主人始终豁免。动态更新只合并该配置项，通过文件锁和原子替换保存，不改变群白名单和其他配置；保存失败时本次进程仍静默拉黑并记错误日志（`tests/test_moderation.py`）。
- **自动拉黑**：触发机器人的群友消息若明确要求大量数字/重复输出，或直接要求忽略规则，先由保守的本地规则拦截，不调用模型。其他明确恶意请求可由模型返回单一的内部标记，桥接仅拉黑该事件的实际发送者；模型不能指定第三方或修改配置，内部标记不发到 QQ。复杂题、普通技术讨论和引用注入案例不能单独作为恶意依据。识别不能保证覆盖所有变体，也可能误判，主人可解除拉黑。
- **群聊上下文**：群里所有文字消息都会被记录，即使没有触发回复。每群保留最近 100 条，每条最多 1000 字。回复时取触发消息之前的最多 40 条、共不超过 12000 字，作为话题参考附在本轮消息前；明确标注不是指令（`remember_group`、`group_reference`，`test_quiet_group_messages_are_reference_without_triggering_reply`）。
- **读取的内容**：只读取文字段、@ 段、图片段和文件段。回复引用、合并转发、语音、视频、表情包等其他类型会被忽略。
- **去重**：同一条消息只处理一次，按消息 ID 记录 7 天。
- **长度**：单条消息超过 6000 字时不交给模型，回复提示拆分。

## 会话

- 每个会话对应一条持久的 Codex 线程：主人私聊一条，每个群一条；主人在群里另有一条单独的操作线程，不与群友的聊天线程混用（`conversation_key`，`test_chat_passes_permissions_and_resumes_separate_threads`）。
- 桥接重启后会恢复原线程，上下文不丢失。
- 桥接每轮重新读取 `workspace/SOUL.md` 和 `workspace/OWNER.md`，依次注入，OWNER.md 仅限核验主人会话，缺失则跳过，修改后下一条消息生效；AGENTS.md 仅由 Codex 原生加载，不再手动注入。
- 详细的线程映射和终端接续方法见 `docs/APPSERVER-MIGRATION.md`。

## 回复

- **主人**：回复流式发送，按段落、列点、句子切成多条 QQ 消息（`reply.BubbleStream`，`tests/test_qq_reply.py`）。Codex 的中途发言和计划更新以"【进度】"消息推送；工具调用摘要只在 `show_tool_progress` 开启时推送（`progress_text`，`test_tools_hidden_by_default`）。
- **群友**：整轮结束后发送，不推送进度；最多 500 字加省略号，超过 200 个数字字符时改为简短拒绝，避免向 QQ 刷长数字。该限制约束 QQ 发送内容，不能保证模型本轮不消耗 token。
- **复杂题与恶意请求的语气**：工作台规则允许对恶意消耗资源、注入和骚扰强硬回击，但拉黑后保持沉默；正常复杂题先要求费用或算力预算，数学题仍需主人授权。不会索要 API 密钥或登录凭据，付费不改变权限。
- **通用限制**：所有消息（含进度）发送限速间隔每次随机取 2～3 秒；单条超过 1600 字时拆开发送。
- **自动 @**：群聊回复 `mention_qq` 里的人时，会在开头 @ 对方。
- **失败**：出错时回复"这次回复未能完成"，并中断 Codex 的当前回合。Codex 请求交互式审批时一律拒绝（QQ 端无法审批）。

## 图片与附件

### 语音回复

- 可选 `voice.enabled`，默认关闭；开启后主人和允许聊天的群友、访客的正常最终回复均先发文字，再异步发送对应语音。主人文字仍流式发送，语音在本轮成功结束后入队；进度、命令和错误提示不合成。
- 本地爱弥斯 GPT-SoVITS V2Pro ONNX 模型运行于独立 Python 环境；桥接通过 JSON 行协议调用常驻子进程，不加载模型依赖。支持完整模型 CUDA 推理及 CPU 回退；须核对主要会话实际启用了 CUDA，初始化失败或推理异常时先释放失败引擎及异常栈引用，再改用指定 CPU 模型，不把后端静默降级误报为 GPU 成功。无需付费语音 API。
- 语音独立 FIFO 队列最多等待 8 轮，满时只发文字并提示。长正文按最多 140 字分段，不默默截断；代码块和链接用口头提示替代，原文仍在文字消息中。
- 群友先经原有长度、数字和拉黑检查，再将实际发送的文字入语音队列；合成前后与发送前均检查黑名单。目标沿用原消息的 `Source`，不从模型输出中解析目标。
- 仅接受单声道 32 kHz PCM16 WAV，每段最多 120 秒、8 MiB。使用 OneBot `record` + Base64 发送，由 NapCat 转换 QQ 语音，避免依赖与 NapCat 共享文件路径。
- 合成超时、模型错误、发送拒绝时保留文字并提示一次；不自动重发结果不明的语音。断线时清空语音队列并杀死合成子进程，不在重连后重播旧语音。
- 语音合成不占聊天任务队列，文字与语音发送仍共用 QQ 发送限速。语音接收、识别及唱歌尚未实现。安装与验证详见 `VOICE.md`。
- 引擎默认 `cut3`，保留句内逗号；内部句间静音 0.35 秒（可配置 0.3–0.5 秒），每个内部语音片段首尾做 15 毫秒线性淡入淡出（启用时可配置 10–20 毫秒，0 表示关闭），不修改模型包，也不改变采样率或片段长度；可单独用参数回退到 `cut5`、0.3 秒静音和关闭淡入淡出。
- 语音清洗将波浪号转为“！”，省略号转为逗号停顿，删除常见颜文字和 emoji（含连接符、旗帜、肤色及数字键帽）。数字按中文读法转换，支持整数、负数、小数、百分数、带年字的年份和数字范围；前导零及手机号码逐位读。不改动发送到 QQ 的文字原文。
- `tools/benchmark_voice.py` 使用固定测试原文与种子 42，保存 WAV、校验和及计时指标，拒绝覆盖已有样本；不会发送 QQ 消息。参考音频的内容与背景音需人工确认后才修改参考文案，不能用文件名或模型说明代替试听确认。情绪参考切换和独立口语稿仅列入 BACKLOG。
- 经主人明确要求，公开对比音频位于 `samples/voice/2026-10-27/`，包含前后及各阶段生成样本、单独标注的原始参考音频、试听重采样版本和脱离本机配置的指标清单；本地运行目录仍不进入 Git。

- 后端协议可显式指定 `seed`（0 至 2³²−1）和 `temperature`（0.01–2.0）；未指定时为 7 和 1.0，日常回复策略不变。`tools/batch_voice.py` 用常驻进程按种子和 temperature 网格生成 WAV，逐条核对后端返回的实际参数，保存输入、指标及校验和；拒绝覆盖已有目录，不发送 QQ 消息。

## 命令

命令必须单独成一条消息；群里需要同时 @ 机器人或带触发词。

| 命令 | 谁可以用 | 作用 |
| --- | --- | --- |
| `/ping`、`连接测试` | 所有人 | 检查连接 |
| `/help` | 所有人 | 功能简介 |
| `/new` | 主人 | 归档当前会话的线程，下一条消息开始新会话；只影响当前会话 |
| `/session` | 主人 | 查看当前会话的 Codex 线程 ID |
| `/models` | 主人 | 查询当前账号可选模型 |
| `/model` | 主人 | 查询当前会话模型设置，未设置时查询接口型号 |
| `/model 模型名` | 主人 | 切换当前会话模型，保留上下文 |
| `/model default` | 主人 | 解析并恢复 Codex 当前配置的默认模型 |
| `/blacklist` | 主人 | 查看跨群用户黑名单 |
| `/block QQ号` | 主人 | 添加群聊用户黑名单并立即生效、保存 |
| `/unblock QQ号` | 主人 | 解除群聊用户拉黑并立即生效、保存 |

群友发送的其他 `/` 开头的消息一律拒绝。主人发送的未知命令会当作普通消息交给模型（`tests/test_command_auth.py`）。

## 模型切换

- 模型命令由桥接直接处理，仅按主人真实 QQ 号授权，群友和私聊白名单访客在访问模型目录或线程前即被拒绝；处理函数也有独立权限校验。
- 模型目录实时分页读取 `model/list`，仅允许可见模型；不接受任意模型名。不支持图片的模型会在列表和切换确认中提示。
- 选择绑定当前会话和 profile，保存在 `profile_models`；重启和 `/new` 后保留，其他会话、群友及访客不受影响。切换时传入该模型默认推理强度，避免继承不兼容的设置，不修改全局配置。
- 命令校验目录后保存选择，下一轮 `turn/start` 显式传入模型与推理强度，避免已加载线程忽略恢复时的覆盖参数。目录查询或保存失败不改变原选择；后续生成失败会报错，主人可重新选择。新建但尚无对话记录的空线程无法恢复时可重建，数据库中的历史记录不删除。
- `/model default` 用独立空测试线程解析 Codex 配置的默认模型，然后保存当时解析的具体型号；以后全局默认改变时，需要再次执行命令。查询和切换命令本身不生成模型回复。
- 已下线的旧型号不会阻止重新选择可用型号。选择目录不等于后续生成一定成功，额度、服务状态或后端权限变化仍可能导致下一轮报错。

## 运行与可靠性

- 作为 systemd 用户服务 `qq-bridge.service` 运行，进程退出后 5 秒自动重启。
- NapCat 断线后每 5 秒重连一次。
- 单轮对话最长 1 小时，超时后中断。
- `tools/restart_bridge.py` 重启服务；`tools/verify_onebot.py` 只读检查 QQ 登录状态。

## 不支持的功能

- **并行处理**：所有聊天共用一个队列，逐条处理。主人的长任务会让其他聊天一起等待；排队超过 8 条时，新消息会被丢弃，只记日志、不提示发送者。
- **发送文件或图片**：尚未开放；桥接可以发送文字（包括 @）及启用后的语音回复。
- **群友的图片和附件**：群友发的图片不会被读取；只发图不带文字时不回复。
- **其他接收消息类型**：回复引用、合并转发、语音、视频。
- **定时或主动消息**：机器人只在收到消息后回复，不会主动发言。
- **多个主人、按群设置不同权限**。
- **通用按人限流**：自动拉黑处理明确的输出滥用和恶意注入；尚无通用发言频率限制，未被识别的刷屏仍可能占满队列。
- **跨会话记忆**：记忆只存在于各自的 Codex 线程里；`/new` 后从头开始。共享的本地设定来自原生 AGENTS.md 和桥接注入的 SOUL.md、OWNER.md。

## 已知问题

- **历史上下文与文件权限**：OWNER.md 不再注入访客会话，AGENTS.md 与 SOUL.md 不应存放主人私人资料。此变更不会清除旧线程已经收到的资料，且不构成操作系统文件访问隔离；访客仍受禁止工具及读取私人资料的规则约束。
- **触发词按子串匹配**："ams"会匹配 teams、programs 等包含这三个字母的单词，导致误触发。
- **Windows 盘只读只靠提示词约束**：主人会话以 `danger-full-access` 运行，桥接代码本身不限制写入。
- **`history` 表持续增长**：每轮都写入，但只在新线程第一次运行时读取（旧桥接的迁移用途），从不清理。

### 会话推理强度（仅主人）

`/effort` 查询当前模型、强度和支持档位；`/effort 档位` 设置；`/effort default` 恢复当前模型目录默认强度。Codex 按实时目录、Claude 按配置目录校验，不支持的档位或查询失败不更改原设置。按会话和 profile 存入 `profile_models`，旧 Codex 表保留兼容，下一条消息生效，重启和 `/new` 保留，只影响当前主人会话。未选择模型时首次设置会固定当前会话模型；再次 `/model` 切换会重置为所选模型默认强度。
